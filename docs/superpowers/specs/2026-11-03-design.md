# ProcureFlow — design

Date: 2026-11-03. User delegated product and architecture choices and authorized implementation, testing and GitHub push.

## Intent
An independently runnable procurement approvals workspace demonstrating TypeScript, Next.js App Router, reusable components, server/client separation, API integration, forms, accessibility and automated tests seen in Türkiye postings.

## Architecture
Next.js and React with strict TypeScript. Feature modules divide domain policies, application use cases, infrastructure repositories and presentation components. SQLite via better-sqlite3 and SQL migrations provides durable zero-service local development. Repository interfaces make the storage choice replaceable; tenant IDs scope every query. Server components load authenticated initial state. TanStack Query powers interactive filters/mutations; Zod validates contracts; React Hook Form owns form state. Tailwind provides a consistent UI.

## Product behavior
Dashboard metrics derived from persisted records, searchable/status-filtered request list, create request, detail with audit history, submit/approve/reject workflows. Roles requester, approver, viewer. Approvers cannot approve their own requests. Money uses integer minor units, one currency TRY. Atomic optimistic concurrency guards transitions; an audit event is written in the same transaction. Unknown/cross-tenant record returns not found.

## Identity
Local demo accounts only when explicit DEMO_MODE=true. Login uses allowlisted seeded identity plus a per-install DEMO_PASSWORD and opaque random sessions stored as digests in database; HttpOnly SameSite=Lax cookies, Secure under HTTPS. Origin checks on mutating routes, expiry, logout revocation, generic auth failures, local persistent login throttle. No self-service registration/OAuth claims. Production startup rejects demo mode unless explicitly enabled; README clearly labels deployment limits.

## Constraints
Use current patched Next.js 16/React 19 compatible packages, pin lockfile. Semantic keyboard-accessible desktop/mobile UI with loading/empty/error states. No outbound mail, real purchasing or paid integrations. Dockerfile and CI. No Sites hosting/deploy; user explicitly requested Next.js source and GitHub.

## Choices
Chosen: one feature-oriented full-stack application with repository ports; SQLite suits a single-node portfolio and CI. Alternative: PostgreSQL service increases local prerequisites and can be added behind repository. Alternative: client-only localStorage app cannot demonstrate authorization or durable concurrent updates. No Redux/Zustand when TanStack Query and local form state suffice.

## Quality / acceptance
Domain tests pin validation, role/ownership rules, state transitions, amount limits and optimistic conflicts. Real SQLite repository tests pin rollback, audit, tenant isolation and concurrent revisions. Component tests verify accessible forms and errors. Playwright exercises real login, create/submit, separate approver decision, viewer denial, cross-tenant access, persistence and mobile. Lint, typecheck, unit suite and production build pass before push; CI reruns. Documentation includes architecture diagrams, ADRs, threat model, feature-to-job matrix, quickstart and validation limits.
